# Monitoring the pipeline

The admin endpoint (`admin.listen`, e.g. `:9180`) exposes the pipeline's own
health. Scrape it with Prometheus alongside the telemetry it exports.

| Endpoint | Use |
|---|---|
| `/healthz` | Liveness: the process is serving |
| `/readyz` | Readiness: 200 while running, 503 while starting or draining |
| `/metrics` | Self-metrics (below), plus Go runtime and process metrics |
| `/debug/pprof/` | Profiling, only when `admin.pprof: true` |

## Self-metrics

Plugin metrics carry an `input="<name>"` or `output="<name>"` label naming the
configured plugin.

### Flow

| Metric | Type | Meaning |
|---|---|---|
| `pipeline_input_metrics_total{input}` | counter | Metrics received from each input |
| `pipeline_router_queue_batches` | gauge | Router backlog. Sustained > 0 means processors or outputs are the bottleneck. |
| `pipeline_router_metrics_total` | counter | Metrics that passed the processors |
| `pipeline_router_filtered_total` | counter | Metrics removed by processors |
| `pipeline_output_enqueued_total{output}` | counter | Accepted into an output queue |
| `pipeline_output_written_total{output}` | counter | Successfully delivered |
| `pipeline_output_dropped_total{output,reason}` | counter | `queue_full` (output too slow) or `write_failed` (permanent error or retries exhausted) |
| `pipeline_output_write_errors_total{output}` | counter | Failed write attempts, including ones that later succeeded |
| `pipeline_output_write_duration_seconds{output}` | histogram | Write latency |
| `pipeline_output_batch_size{output}` | histogram | Metrics per write |

### Inputs

| Metric | Meaning |
|---|---|
| `gnmi_target_up{input,target}` | 1 while the subscription is established |
| `gnmi_session_failures_total{input,target}` | Sessions that ended with an error (each is followed by a redial) |
| `gnmi_sync_responses_total{input,target}` | Initial-state syncs completed |
| `gnmi_notifications_total{input,target}` | Notifications received |
| `gnmi_unsupported_values_total{input,target}` | Values that can't be decoded generically (`any`, `proto_bytes`) |
| `mdt_connections{input}` | Open dial-out sessions |
| `mdt_messages_total{input}` | Messages received |
| `mdt_decode_errors_total{input,reason}` | `malformed`, `compact_gpb`, `framing` |

### Outputs

| Metric | Meaning |
|---|---|
| `prometheus_exporter_series{output}` | Series currently exposed |

## Dashboards

Four Grafana dashboards ship in
[`deploy/grafana/dashboards`](https://github.com/sangmeshcp/bigmuddy-network-telemetry-pipeline/tree/master/deploy/grafana/dashboards):

| Dashboard | Shows | Data needed |
|---|---|---|
| **Telemetry pipeline: health** | ingest, delivery, drops, write latency, router backlog, gNMI targets, MDT sessions, CPU and memory | the admin endpoint (`/metrics` on `:9180`) |
| **Interfaces (OpenConfig / gNMI)** | throughput, errors, discards, top talkers, oper/admin status | `/interfaces` subscriptions; `string_fields: info` for status |
| **Interfaces (Cisco IOS XR / MDT)** | throughput, packets, errors, CRC, drops | MDT sensor path `Cisco-IOS-XR-infra-statsd-oper:infra-statistics/interfaces/interface/latest/generic-counters` |
| **BGP (OpenConfig / gNMI)** | sessions established / not, session-state table, prefixes received and installed | `/network-instances` subscription; `string_fields: info` |

How to install them:

- **Compose lab:** already provisioned in the *Network telemetry* folder.
- **Kubernetes:** `--set grafanaDashboards.enabled=true` on the Helm chart
  creates ConfigMaps labelled `grafana_dashboard: "1"` for the Grafana
  sidecar (e.g. kube-prometheus-stack).
- **Any Grafana:** *Dashboards → New → Import* and upload the JSON. Each
  dashboard has a data-source selector.

The dashboards are generated by `deploy/grafana/generate.py` (run
`make dashboards` after editing). CI runs **every panel query and template
variable** against Prometheus fed by a live pipeline (OpenConfig reference
gNMI target + replayed IOS XR telemetry), so a renamed metric or a broken
query fails the build.

## Alert rules

[`deploy/prometheus/alerts.yaml`](https://github.com/sangmeshcp/bigmuddy-network-telemetry-pipeline/blob/master/deploy/prometheus/alerts.yaml)
holds the recommended rules, each with a summary, a description and a link
to the relevant troubleshooting section. They are unit-tested with
`promtool test rules` in CI.

| Alert | Severity | Fires when |
|---|---|---|
| `TelemetryPipelineDown` | critical | the admin endpoint can't be scraped for 2m |
| `TelemetryNoIngest` | warning | an input received nothing for 15m |
| `GNMITargetDown` | warning | a gNMI subscription is down for 5m |
| `GNMITargetFlapping` | warning | more than 3 session failures in 15m |
| `TelemetryOutputDropping` | critical | an output drops data for 10m |
| `TelemetryOutputWriteErrors` | warning | an output's writes keep failing for 15m (still retrying) |
| `TelemetryRouterBacklog` | warning | the router backlog stays above 100 batches for 10m |
| `MDTCompactGPB` | warning | a device sends compact GPB |
| `InterfaceOperDown` | warning | an interface is admin-up but oper-down for 2m (OpenConfig) |
| `InterfaceInputErrors` | warning | more than 1 input error/s for 10m (OpenConfig) |
| `XRInterfaceCRCErrors` | warning | CRC errors for 10m (IOS XR MDT) |
| `BGPSessionNotEstablished` | critical | a BGP session isn't ESTABLISHED for 5m (OpenConfig) |

How to install them:

- **Prometheus:** add the file under `rule_files:`. The Compose lab does this.
- **Prometheus Operator:** `--set prometheusRule.enabled=true` on the Helm chart.

The pipeline alerts expect the admin endpoint's scrape job name to contain
`pipeline`; adjust the `job=~` matcher if yours differs.

## Useful queries

```promql
# Ingest rate per input
sum by (input) (rate(pipeline_input_metrics_total[1m]))

# Delivery ratio per output (should be 1)
sum by (output) (rate(pipeline_output_written_total[5m]))
  / sum by (output) (rate(pipeline_output_enqueued_total[5m]))

# p99 write latency per output
histogram_quantile(0.99, sum by (output, le) (rate(pipeline_output_write_duration_seconds_bucket[5m])))

# Targets currently down
gnmi_target_up == 0
```
